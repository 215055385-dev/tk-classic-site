# TK Classic Independent Website

Official B2B independent website for TK Classic portable coffee machines, OEM/ODM programs, private label sourcing, accessories, certificates, and buyer inquiries.

## Tech Stack

- Next.js App Router
- React 19
- TypeScript
- Tailwind CSS v4
- Supabase Auth, PostgreSQL, and Storage for the CMS
- Prisma ORM 7 with the PostgreSQL driver adapter
- Static product/content data in `lib/site-data.ts`
- Product assets and downloadable PDFs in `public/`

## Main Routes

- `/` — multilingual homepage with product line, OEM/ODM service, certificates, FAQ, and inquiry form
- `/products/[slug]` — static product detail pages generated from `lib/site-data.ts`
- `/robots.txt` — generated by `app/robots.ts`
- `/sitemap.xml` — generated by `app/sitemap.ts`

## Content Maintenance

Most buyer-facing content is centralized in `lib/site-data.ts`:

- `company` — brand, legal name, contact details, brochure path
- `languages` — supported language codes and text direction
- `copy` — homepage, FAQ, form, and UI labels for each language
- `products` — product summaries, images, specs, highlights, and use cases
- `accessories` — accessory cards
- `certifications` — downloadable certificate links

When adding a new product:

1. Add product images under `public/products/{slug}/`.
2. Add the product record to `products`.
3. Confirm the model appears in the inquiry form product selector.
4. Confirm certificates and claims apply to the new model.
5. Run `npm run build`.

## SEO Notes

The current site supports multilingual content through the `lang` query parameter. For stronger international SEO, consider migrating to path-based locale routes such as `/en`, `/es`, `/zh`, and adding localized canonical/hreflang URLs.

Current SEO basics included:

- Global metadata
- Product page metadata
- Sitemap
- Robots
- Organization, Product, and FAQ structured data

## Inquiry Flow

The inquiry form submits to `app/api/inquiries/route.ts`.

Production environment variables:

- `DATABASE_URL` — Neon Postgres connection string for inquiry storage
- `RESEND_API_KEY` — Resend API key for email notifications
- `INQUIRY_TO_EMAILS` — comma-separated recipients, defaults to `ryan@tkclassic.com,fyhi7576@outlook.com`
- `INQUIRY_FROM_EMAIL` — sender identity, defaults to `TK Classic Website <onboarding@resend.dev>` for initial Resend testing

The API stores each inquiry in an `inquiries` table and sends the sales team an email notification. Use a verified Resend sender domain before switching from the testing sender to a `tkclassic.com` address.
